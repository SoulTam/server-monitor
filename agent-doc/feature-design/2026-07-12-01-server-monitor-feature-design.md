# 功能设计文档 — 日志尾部浏览 & 单实例锁

## 功能 1：日志尾部浏览

### 用户故事
作为运维人员，我打开一个很大的应用日志文件时，希望立即看到最新产生的日志内容，而不是从头开始手动滚动到底部。

### 交互流程
```
用户点击"浏览日志"
  → 弹出日志弹层
  → 用户点击文件列表中的某个文件
  → 系统 SSH 执行 tail -n 500 读取末尾 500 行
  → 内容展示在右侧，自动滚动到底部
  → 用户向上滚动（接近顶部）→ 自动加载更早的 500 行并插入到内容顶部
  → 用户向下滚动到底部 → 自动跟随最新内容
  → 每隔 5s 检查文件是否有新行 → 追加到内容底部（用户在底部时自动跟随）
```

### 交互变化
| 现状 | 变更后 |
|------|--------|
| 打开文件从 offset 0 开始读，需手动滚动到底部 | 打开文件直接展示末尾 500 行，自动定位到底部 |
| 向下滚动触发加载更多（旧到新） | 向上滚动触发加载更早（新到旧） |
| 无实时更新 | 5s 轮询追加新行 |

### UI 变化
日志内容区右下角新增浮动按钮（切换头部/尾部浏览模式）：
```
[↓ 最新] [↑ 历史]
```

## 功能 2：单实例锁

### 用户故事
作为桌面用户，我双击桌面快捷方式多次时，不希望打开多个监控窗口，而是聚焦已打开的那个。

### 交互流程
```
用户双击 Server Monitor 快捷方式（首次）
  → app.requestSingleInstanceLock() → true
  → 正常启动，创建主窗口

用户再次双击 Server Monitor 快捷方式
  → app.requestSingleInstanceLock() → false
  → app.quit() → 触发 'second-instance' 事件
  → 已有窗口 show() + focus()
```

### 交互变化
| 现状 | 变更后 |
|------|--------|
| 多次点击快捷方式会创建多个独立进程 | 只能有一个进程，后续操作聚焦已有窗口 |
| 用户可能困惑哪个窗口在用 | 直接弹出已有窗口，体验统一 |
