# 方案讨论：日志中嵌套 JSON 字符串的展示（讨论阶段产出，不含代码）

## 0. 现状梳理（来自代码阅读）

```
原始日志行：{"level":"info","context":"{\"userId\":123,\"action\":\"login\"}","msg":"..."}
                                  └─ 这是一个 JSON 字符串（value 是字符串，内含转义 JSON）
```

`formatJsonLine` 现状：

```ts
function formatJsonLine(line: string): string {
  try {
    return JSON.stringify(JSON.parse(line), null, 2);   // ← 只对"行是 JSON"做格式化
  } catch {
    return line;
  }
}
```

问题：`JSON.parse` 后内层 `context` 仍是字符串 `"{\"userId\":...}"`，`JSON.stringify(.., null, 2)` 会**带转义字符**原样输出，等于没拆开。

约束（已确认）：

| # | 约束 | 来源 |
|---|------|------|
| 1 | 只前端；不改 raw value 字符串内容 | 用户确认 |
| 2 | 仅 depth=1（一次 JSON-in-JSON） | 用户确认 |
| 3 | 允许视觉处理（颜色、虚线框、徽标等） | 用户确认 |
| 4 | 浮窗高度自适应 + 自带滚动条 | 用户确认 |
| 5 | 只读、可复制、不可修改 | 用户确认 |
| 6 | 不引入新依赖（可商榷，但默认不引入） | 项目已有 antd + monospace 渲染；引入库=评审成本 |

---

## 1. 候选方案

### A. 用户原案 — Hover 在 key 上显示右侧浮窗
- 思路：检测 `value` 是否为合法 JSON 字符串；如是，把 key 标"高亮徽标 + 颜色"，`onMouseEnter` 打开右侧浮窗展示 pretty-print。
- 触发：hover key；关闭：hover leave / 点击空白 / Esc。
- 定位：`fixed` + `getBoundingClientRect` 计算右侧偏移；超出视口则 flip 到左侧。

### B. 原地"低饱和"展开（轻量 inline preview，不叠加浮窗）
- 思路：识别嵌套 JSON 字符串后，**就地**用灰色、italic、行内嵌套 `<pre>` 块展示 pretty-print；保留原始转义形式不变。
- 触发：直接渲染，**无需用户悬停**。可加一个 "折叠/展开" 切换按钮。

### C. 工具栏切换模式 — "原始/美化" 双视图
- 思路：在 Modal 顶栏加一个切换：原始 (current) vs. 美化 (递归 pretty)。后者把每个 JSON 字符串在原位置 indent 替换为语法树形式。
- 切换作用域：当前文件 / 全局（带 localStorage 记忆）。

### D. 复合方案 — A + 内联可展开折叠
- 默认与 B 一致：嵌套 JSON 直接以"已 pretty"形式替换右侧 value 区域；外加一个"复制原始""复制 pretty"小图标 + 折叠按钮；当 pretty 体积超过阈值（如 600px 高），自动折叠成单行 + 角标"⋯"。

## 3. 推荐方案：**D（精简版）= B 的"就地替换" + 折叠 + 可复制"原始 / 漂亮"**

> 用户原文里的"hover 浮窗"是被多次吐槽过的反模式（键盘不可达、滚动时浮窗错位、滚动条 1000+ 行时会闪），但在当前这个场景下，用户的隐含需求其实只是 **"我能看清那个内层 JSON 又不污染主日志视觉"**。

最贴合既有 `formatJsonLine` 思路的做法：

**核心渲染规则（终态描述，本阶段不动手）：**

1. **解析分级**：`parsed = JSON.parse(line)` 之后，再 `Object.entries(parsed)` 扫一遍每个 value：
   - 若 `typeof v === 'string'` 且 `tryParse(v) === ok` → 命中 `nested-json-string`
2. **第一次 pretty 不变**：`formatJsonLine(line)` 输出当前 4-space 已生效版本（用于"raw 完整原文"备份）。
3. **新渲染产物**：在原行区域用 React 节点替换 value 部分：
   ```jsx
   <span class="json-key">"context"</span>:
   <span class="json-value-nested">
     {/* 默认形态：折叠，角标：内嵌 JSON，体量 hint */}
     <span class="json-fold-inline">▶ nested JSON ({ pretty.length } chars)</span>
   </span>
   ```
4. **就地展开（点 ▶ 而非 hover）**：点开后**替换**为 pretty 块：
   - 高度自适应（外部容器 max-height: clamp(120px, calc(100vh - 240px), 480px); overflow:auto），`🟦 overflow: scroll` 内置滚动。
   - 右上角两个 icon button："复制 raw" / "复制 pretty"，复制用 `navigator.clipboard.writeText`。
   - 操作栏自带键盘可达 `<button>` + Esc / 点击其他位置自动折叠。
5. **边界**：
   - 单文件首屏仅替换"可见区域"内的命中项；超过 `max-height` 自动折叠，未点击不强制 pretty（懒渲染）。
   - 滚动到底加载新分片时同样按需渲染。
6. **不破坏**：
   - `<mark>` 搜索高亮继续生效（命中是被替换前文本的索引）。
   - 复制拖选仍然能选整行（被替换节点用 textContent 实时回填）。
   - "已加载全部内容"/"加载中"等提示仍可用。
7. **可发现性**：折叠处打开后用浅蓝色背景 + italic 区分"次级数据"；视觉一致 antd 风格。

### 三个关键决策的可解释性

- **为啥不直接 hover 浮窗？** 日志是滚动长列表，hover 在顶部 key、滚到底部时 DOM 已卸载，浮窗要么抖动要么丢失焦点。键盘用户不可达。需要点击触发（更明确、更可发现、可键盘操作）。
- **为啥就地替换而非新视图模式？** "日志查看窗口"的核心任务就是看日志。再开一个"美化视图"切换会让用户每次分辨"我现在看的是哪一版"，心智成本高。原位替换 = "所见即所是"。
- **为啥提供"复制 raw"按钮？** 用户明确"不影响原本日志的内容" — 但 pretty 后用户想抄回原值时还有一个 1-click 通道。这是补充约定。

---

## 4. 小结

- 用户原案 A 在评估上未处于最优，但仍是 4 个方案中**可接受**的第 2 选择。
- 推荐 D（即"B + 折叠 + 复制按钮"）。
- 若你要最简单路径：**B（inline 替换，不带折叠按钮，每次直接展开，但 max-height 限制在小）**。
- 若你要保留原方案：选 A — 我会**改用点击触发 + 自适应滚动**，但**不强制增减按钮**。
